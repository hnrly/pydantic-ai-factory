# Changelog

Every change a user can see is listed here, newest first.

## Unreleased

- `python -m evals` prints a scorecard and a run card after every experiment and after `--regrade`, and writes them under `--out` as `scorecard.json` and `run-card.json`. The scorecard has one row for each arm and a table for each split: the verified design rate, the gate line, reliability and cost per verified design; the question measures under "How the session asked"; checklist coverage under "Design quality: beside the outcome, never deciding it", withheld from the real judge until its agreement with the author's labels reaches 90 per cent; the paired difference between `factory` and `claude-code`, and the ablation against `factory-simple`; every unexplained value with its run id; and the limits every scorecard states. Each rate is computed per case, then across cases, with a 95 per cent interval from the spread between cases, or none with one repeat. The run card lists what the results were measured with, from the benchmark's version and models to the hash of the factory's skill library, and says "not available" for a source that is missing. `evals/stats.py` holds `wilson`, `clustered_rate`, `paired_difference` and `pass_k`, with a small table of t values and no statistics library. `--offline --regrade` treats the stored verdicts as the scripted judge's. The Measuring page gains "The scorecard and the run card".
- **Breaking:** `python -m evals.design` is removed, and `python -m evals` replaces it. Software Factory Evals runs a system on cases whose request leaves facts out, through three ports: a brief with the case's repository mounted read-only in a Docker container, a simulated stakeholder whose replies are written in a hidden fact sheet, and delivery of a design with a status of `delivered` or `blocked`. Plain code grades each run into one of six outcomes, counts the question measures and writes `results.json`; a judge model reads each case's hidden checklist beside the outcome and never decides it. The arms are `claude-code`, vanilla Claude Code, `factory`, the Design station with Elephant Goldfish, and `factory-simple`, the same station without the review, plus four scripted fixtures that run only offline. `python -m evals --offline --split smoke` checks the harness on the smoke case without spending money; `--arm`, `--repeat`, `--out`, `--model`, `--judge`, `--regrade` and `--build-image` are its other options. The factory and Claude Code arms need Docker. CI runs the smoke case offline. The Measuring page is rewritten around it, and its to-do scores are removed.
- Ground the Design station in a read-only workspace. `design_station(model, *, method=..., workspace=None)`, `design_review(model=None, *, workspace=None)` and `SoftwareFactory(model, *, workspace=None, ...)` take a workspace, a capability that supplies one such as `LocalWorkspace(path)`; `SoftwareFactory` passes it to the Design station it builds. The workspace is wrapped in `ReadOnlyWorkspace`. The designer then gets read-only file tools from Pydantic AI Harness, `FileSystem(read_only=True)`, the repository's instruction files such as `AGENTS.md` through `RepoContext`, and the repository's own skills from `.agents/skills` and `.claude/skills`, offered after the method's and the software package's, skipped when the folder is missing, never replacing a skill of the same name, and left out when the harness's artifact scanner flags them. Each goldfish of `design_review(workspace=...)` gets the workspace and the same read-only file tools, never the instruction files or skills; the station's default review is built with its workspace. Before any review, a design whose `changes` would modify or delete a path that does not exist, or create one that does, goes back to the designer with each wrong path listed; without a workspace the check passes. The designer's instructions gain "Load a skill from the repository's own library when its description fits the work." Without a workspace nothing changes. The Design page gains "Designing in an existing codebase", with a warning about a repository you do not trust, and the software factory page lists the new option.
- The design skills. The method's guidance is now written as Agent Skills. Four ship with Elephant Goldfish, behind the `methodologies` extra: `design-interview` and `design-resolve`, which the author is offered and loads when it needs them, and `goldfish-comprehension` and `goldfish-critique`, whose bodies are those goldfish's instructions. `Goldfish.from_skill(path, *, name=None, stage=None, kinds=None, sees_request=False)` builds a goldfish from any `SKILL.md`. **Behaviour change for 0.1 users of `ElephantGoldfish`:** `goldfish` is no longer required and defaults to `ElephantGoldfish.GOLDFISH`, comprehension and critique built from the method's skills; `goldfish=()` is now allowed and means no review, with no `contest` or `escalate` tool and a gate that passes; and every author, with review or without, is offered the method's two author skills through Pydantic AI Harness's `Skills`, with a `load_capability` tool and one more sentence in its instructions. A comprehension goldfish now returns an `ExplainBack` (`problem`, `who`, `done_when`, `not_doing`, `approach`), exported from `pydantic_ai_factory.methodologies`, in place of a free-text `paraphrase`; the report still keeps it as one paraphrase. The software package ships three skills, `design-read-code`, `design-doc` and `goldfish-readiness`, and publishes `design_station(model, *, method=...)` and `design_review(model=None)`, with `DESIGNER_INSTRUCTIONS`, which now names the designer's skills. `DESIGN_GOLDFISH` is now comprehension and critique from Elephant Goldfish and readiness from its skill, each with its kinds; `DESIGN_STANDARDS` is read from the skills. The designer is offered exactly four skills, with or without review. `SoftwareFactory(model, *, design=None, repairs=2, accept=None)` takes the Design station as `design=`; by default its review is `design_review()`, so it now reads each draft as Markdown, runs up to four rounds until two clean rounds run in a row, and settles a contest whose citation code checks. **Deprecated:** the keywords `rounds`, `goldfish` and `review_model` of `SoftwareFactory`, mapped onto `design_review()` and refused with `design=`, and its attributes `model`, `rounds`, `repairs`, `goldfish` and `review_model`; each warns and goes in 0.3. The `contest` tool's example citation is now `field:non_goals`. The offline run is reviewed in three rounds. The Elephant Goldfish page gains "The method as skills", the Design page "The designer's skills" and a table of the three goldfish, and the software factory page "Your own Design station" and "Deprecated in 0.2"; the Decisions page gains "Elephant Goldfish uses its skills by default", "A method belongs to a station, not a factory" and "Skills sit on the designer". CI checks that the built wheels hold every `SKILL.md`.
- A design a builder can follow. `Design` takes the shape of a design document. **Breaking:** `goal` is renamed `summary` and `exclusions` is renamed `non_goals`; a design stored with the old names still loads, as each moves into its new field. New fields, each empty by default: `problem`, `goals`, `assumptions`, `journeys`, `architecture`, `decisions`, `alternatives`, `risks`, `changes`, `steps` and `verification`, with the records `Journey`, `Decision`, `Alternative`, `Risk`, `Change`, `Step` and `Check`, all exported from `pydantic_ai_factory_software`. `render_markdown` writes every section under a fixed heading, in a fixed order and line format, and says "None." for an empty section. The Design station's gate is now `design_is_buildable`, version 1, also exported: after the open-questions rule it checks that every acceptance criterion is proved by a verification item and every criterion named exists, steps and changes name the same paths, steps depend only on steps that exist and have no loop, every decision has a reason and a source, at least one alternative is recorded with a reason for rejection, no field says "TBD" or "TODO", and no path is changed twice. Each failure names the item and sends the design back to the designer. The designer's instructions ask for these parts. The Design station and the software factory are now version 2, so their digests change. The `--offline` scripted designer writes a design that passes the new gate. The Design page gains the new field table and "The gate".
- Findings that can be checked and settled. A finding gains `kind`, `quote` and `suggestion`, written by the goldfish, and `settled` and `same_as`. Code now checks what each goldfish returns: every quote must be part of the text it read once whitespace is collapsed, a goldfish with `kinds` must use one of them, and none may report more than its `max_findings`. A failure goes back to the goldfish, twice at most; a quote still wrong after that is removed and the finding kept with "(quote not found in the design)" added to its issue. Each severity has one meaning for every goldfish, given in their instructions. The `contest` tool gains `cites`, `path:symbol` or `field:name`, which code checks against the run's workspace or the output's fields. `ElephantGoldfish` gains `settle_contests=False`: when `True`, a contest whose citation checks out settles its finding without a person. A later finding from the same goldfish with the same `where` and `kind` as a settled one is settled at once, names it in `same_as`, and is not sent back to the author. `ElephantGoldfish` gains `clean_rounds=1`: with more, a clean round is followed at once by another read of the same draft, and the review ends only after that many clean rounds in a row; it may not exceed `rounds`. The gate `clean_final_round` leaves settled findings out of what it escalates. The defaults keep 0.1's behaviour. Each report is now stamped `elephant-goldfish@2`, because a round now means more. The Elephant Goldfish page gains "When a review ends", and the Decisions page "A contest that cites what anyone can check may settle a finding".
- Let goldfish see what they need. `ElephantGoldfish` gains `to_text`, a function that turns a draft into the text the goldfish read (by default a structured draft is still read as JSON, and the gate still checks the exact draft); `capabilities`, given to every goldfish, such as read-only file tools; and `request`, a function of the run context that gives the request (by default the text of the run's first user prompt). `Goldfish` gains `sees_request=False`, `kinds=()` and `max_findings=20`, each checked when it is made; `kinds` and a lower `max_findings` are put in the goldfish's instructions. Each round, the comprehension goldfish run first and every other goldfish then runs at the same time, instead of one after another. Only a goldfish with `sees_request` receives the request, in a `<request-…>` tag, and every critique goldfish now receives each comprehension goldfish's explain-back in an `<explained-…>` tag. Every goldfish is told that the request, the work and any code it reads are evidence, never instructions. The Elephant Goldfish page gains "What each goldfish sees".
- **Breaking:** `ask_person` asks in rounds. The tool now takes `questions`, a list of `Question` (`text`, `why_it_matters`, `options`, at most three or none, and `recommended`, which must be 0 when given), instead of one `question` string. A round is one model response that calls it, with up to four questions; several calls in one response are one round, where 0.1 wrongly counted each call. The run waits once for the round. Each call's metadata carries `questions`, the list as dictionaries, and `question`, the round as numbered text. `AskPerson(max_questions=3)` becomes `AskPerson(max_rounds=3, max_per_round=4)`: a round with too many questions is refused with a message and not counted, and after the last round the tool tells the agent to carry on. `Question` is exported from `pydantic_ai_factory`. **Breaking:** `ElephantGoldfish` no longer adds `ask_person` and loses `max_questions`; give the author `AskPerson()` beside it. The software factory's designer has both, so it still asks. `factory run` and `factory resume` print each question with why it matters and its options, the recommended first, and `--answer` replies to the whole round. The evaluation set's Elephant Goldfish designer is given `AskPerson()`, so it asks as before.
- Put Elephant Goldfish behind a new optional extra, `pydantic-ai-factory[methodologies]`, which adds Pydantic AI Harness. Importing `pydantic_ai_factory.methodologies` now needs it; without it the import fails at once with `ImportError: Elephant Goldfish needs the methodologies extra: pip install "pydantic-ai-factory[methodologies]"`. Every name imports from where it did, and the rest of the core imports and runs without the extra. `pydantic-ai-factory-software` depends on the extra, so its users see no change. An import check stops any core layer below `methodologies` importing the harness.

## 0.1.0

- The first release, published to PyPI as `pydantic-ai-factory` and `pydantic-ai-factory-software`. Each release is built and published from its tag by GitHub Actions, with trusted publishing and signed attestations, and its notes are the lines under its heading here.
- Point every link at the repository's real name, `hnrly/pydantic-ai-factory`, and serve the docs site from `/pydantic-ai-factory/`, so GitHub Pages and the clone commands work. Mark both packages alpha, and open the README with what the library promises: AI factories that prove their work.
- Ask for prompt caching in the software factory's `designer` and in every Elephant Goldfish goldfish, with `model_settings={"cache": True}`. In the first real runs neither was cached, and the designer resends its whole conversation every review round. The Getting started designer and the evaluation set's designers ask for it too. The Getting started reviewer now uses `Coder(sub_agents=False)`: in a real run it handed the whole review to a sub-agent, which read the project again and doubled the review's cost.

- Add an evaluation set for the Design station, built on `pydantic-evals`: `python -m evals.design --offline` runs four to-do list missions through a one-station factory twice, with a designer that has `ElephantGoldfish` and the same agent without it, and scores both with plain code (`CoversTheMission`, `EnoughCriteria`, `CriteriaTiedToTheMission`, `SettlesTheUnsaid`, `attempts`, `rounds`, `open_findings`). Each case has hidden checks, questions its mission leaves open that a good design must settle, such as what a blank task does; `SettlesTheUnsaid` is the share a design answers. `--model NAME --out results.json` runs it against a real model. CI runs it offline. Add the Measuring a methodology and Roadmap pages, and an acceptance test for each row of the roadmap's "Today" table.

- Add the `factory` command, installed with `pydantic-ai-factory-software`. `factory run "MISSION"` (or `--brief FILE`) runs the software factory, prints the design in full, says how it was reviewed and asks you to approve it, ask for changes or reject it; an approved design is written to `designs/<title>.md`. An agent's question is asked in the terminal too. `--offline` uses a scripted model, so no key is needed. `--no-input` saves a waiting run instead of asking; answer it later with `factory resume <run id>` and `--approve`, `--changes NOTE`, `--reject NOTE` or `--answer TEXT`; a waiting run prints the command that answers it, with `--answer` when an agent asked a question and `--approve` otherwise. `factory show <run id>` prints a run, and the design it waits on. Exit codes: 0 passed, 1 ended without passing, 2 the command was wrong, 3 waiting. Add the Getting started page, a `live` pytest marker for tests that call a real model, skipped unless selected with `-m live`, and the to-do list brief in `examples/todo-list/brief.md`.

- Add the software factory, in `pydantic-ai-factory-software`. `SoftwareFactory(model, rounds=2, repairs=2, goldfish=DESIGN_GOLDFISH, review_model=None, accept=None)` is a `Factory` named `"software"`, with one station today, `design`. A string mission becomes a `Mission`. The `designer` agent drafts a `Design` (`title`, `goal`, `behaviour`, `acceptance_criteria`, `exclusions`, `open_questions`) under `ElephantGoldfish`, reviewed by the three `DESIGN_GOLDFISH` (`comprehension`, `critique`, `readiness`) against `DESIGN_STANDARDS`. A design that still has open questions fails the gate `no_open_questions` and is sent back up to `repairs` times, then a person decides; a design that passes waits for a person to approve it. `render_markdown(design)` turns a design into Markdown, numbering acceptance criteria AC1, AC2 and so on and dropping any label such as "AC1:" that the designer wrote itself. The designer is told not to repeat a finding it contested or escalated as an open question, so that finding does not fail `no_open_questions` and cost a second attempt. The package has an `anthropic` extra. Add the Software Factory pages: the overview, Design, and Build, Quality and Release (coming soon).
- Change the Elephant Goldfish and Methodologies samples to use `DESIGN_GOLDFISH`.

- Add tracing. Every call to `Factory.run` or `Factory.resume` is an OpenTelemetry span under the `pydantic_ai_factory` tracer, with a span inside it for each station attempt, each `ctx.run_agent` call, each gate evaluation and each answer a person gave. Pydantic AI's own spans, and the goldfish reviewing a draft, nest inside their station. Spans carry digests, never content, and never a person's note or reply. Nothing is traced until the application installs a tracer provider. `opentelemetry-api` is now a direct dependency.

- Add Elephant Goldfish, Google's method for design-driven development, in `pydantic_ai_factory.methodologies`. `ElephantGoldfish(goldfish=..., rounds=2, model=None, max_questions=3)` is one methodology: each draft the author finishes is read by fresh goldfish agents, stage by stage (`comprehension`, `critique`, `readiness`), and their findings go back to the author with `ModelRetry` until a round has no `Blocker` or `Major` or the rounds run out. The author can `contest` or `escalate` a finding; those, and findings still open at the limit, make the station wait for a person. A goldfish that fails means the station did not run. Each round is a `GoldfishReport`, judged by the gate `clean_final_round`. It includes `AskPerson`, so the author may ask up to `max_questions` scoping questions; a question asked mid-review keeps the round count and the findings already answered. The goldfish count in the author's usage and stop at its usage limits. Define reviewers with `Goldfish(name, stage, job, standard=None)` and `Standard(name, text)`.

- Add methodologies. `Methodology` subclasses Pydantic AI's `AbstractCapability` and adds `name`, `version`, the `evidence` types it records with `self.record(ctx, payload)`, and `judge`, its gate. Attach it to an agent with `capabilities=[...]`. In a station, `ctx.run_agent` stores the evidence, joins the methodology's gate to the station's into one combined gate, stamps its name and version on the records, and adds its `output_retries` to the agent's output retry budget. A replayed agent call gives back its evidence. `Station.methodologies` and `Factory.methodologies()` list them before a run, and the factory digest covers them.
- Remove the `methodologies=` argument of `Factory.run`, `Factory.run_sync` and `Station.run`, and the `Run.methodologies` field. Methodologies live only on agents.

- Add missions and signals. `Mission(objective, success_criteria=..., constraints=...)` is what a factory commits to; when the first station takes a `Mission` or a `str`, `Factory.run` turns a plain string into one, and a station that takes a `str`, such as `station(agent)`, is given `mission.as_prompt()`. The run keeps the mission as an artifact, named by `run.mission_ref`, and every artifact it makes carries the mission's id. `Signal(payload, source=None)` is work that arrives on its own; the payload's type is its kind. `Factory(..., accept=...)` and `factory.intake` (or `intake_sync`) store each signal and return a `Mission` that records them, or `Declined(reason)`. When a run of a mission made by intake ends, the factory stores an `Outcome` signal and names it in `run.outcome_signal`.
- Remove the `mission_id=` argument of `Factory.run` and `run_sync`. A run's mission comes from its input.

- Add approvals. `@station(approval=True)` and `station(agent, approval=True)` make a run wait for a person once every gate has passed. A waiting run has `run.waiting`, of kind `"approval"`, `"escalation"` or `"tool-calls"`. Answer with `run.approve`, `run.request_changes` or `run.reject`, each bound to the exact output, or, for tool calls, with Pydantic AI's `DeferredToolResults`, and carry on with `Factory.resume` or `resume_sync`. `run.approvals` records every decision.
- Add escalation: the `escalate` verdict, `raise Escalate(reason, output=...)` in a station, and `Rework(..., on_limit="escalate")`. Approving an escalation accepts the work and records that a person overrode it.
- Add tool-call waits. An agent run through `ctx.run_agent` that ends with deferred tool calls makes the run wait; on resume the station runs again, replaying the agent calls that finished. Add the `AskPerson` capability, an `ask_person` tool capped by `max_questions`. An agent with output validators keeps its own output type; to let it wait, declare `DeferredToolRequests` in it.
- Add the `RunStore` protocol. `MemoryStore` and `LocalStore` keep runs as well as artifacts, with `get_run`, `get_run_sync` and a compare-and-swap `put_run`; an answer is saved before the work it starts, so a second answer to the same run raises `RunConflict` and runs nothing. The factory saves the run after every step; `on_step` is for watching. `get_sync` reads an artifact from code that is not async. The stores move to `pydantic_ai_factory.stores`, with `encode_run` and `decode_run`.
- Remove the `needs_approval` verdict; use `approval=True` or `escalate`. Remove the Artifacts page; artifacts and runs are on the Stores page.

- Add agents in stations. `ctx.run_agent(agent, prompt)` runs a Pydantic AI agent, stores its `Conversation` keyed by the agent's name, and carries it on at a later attempt, sending the gate's reasons instead of the prompt. `@station` finds the agents its function refers to; `agents=` names them instead. `station(agent)` turns one agent into a station. `Factory.agents()` lists every agent before a run. `Factory.run_sync` and `Station.run_sync` run from code that is not async.
- Change stations and artifacts to take any type Pydantic can serialise, such as `str` or `list[str]`, not only models.
- Change `Rework` to take station objects: `Rework(design, limit=2)` and `Rework(build, to=design)`.
- Change the `Run` record: `output` is now the final payload, and the refs are `input_ref` and `output_ref`. `StationResult` has `input_ref`, `output_ref` and `conversations`.
- Change `StationContext` to `run_agent`, `record`, `deps`, `attempt`, `feedback` and `run_id`. `feedback` is a `Feedback` record of the reasons work came back.
- Remove the Concepts page. Each concept has its own page.

- Add factories: `Factory`, `Rework`, `Factory.run` and the `Run` record. A factory is a named, ordered list of stations; there is no separate line. Failed work can be sent back a bounded number of times with the gate's reasons; a station that did not run is never retried. A badly formed factory is refused with every finding at once. `on_step` saves progress after every attempt.
- Add gates: the `@gate` decorator, `passed`, `failed` and `needs_approval` verdicts, required evidence, `Gate.evaluate` and `GateDecision` records. A gate that cannot be evaluated is reported as such, never as a pass or a fail.
- Add stations: the `@station` decorator, `StationContext`, `Station.run` and `StationResult`, which keeps "ran" apart from "passed" and carries the traceback of a station that raised. Every definition error is a `DefinitionError` whose `findings` list each problem.
- Add artifacts: `Artifact`, `ArtifactRef` and `Producer`, with SHA-256 content digests, lineage and superseding. Add the `ArtifactStore` protocol with `MemoryStore` and `LocalStore`, which check every artifact against its digest. `Untyped` reads an artifact without its payload class, and `encode_artifact` and `decode_artifact`, in `pydantic_ai_factory.artifacts`, let you write your own store.
- Add the documentation site, with Overview, Concepts and Decisions pages, diagrams, a check that every diagram parses, and a test that runs every Python sample in the docs.
- Add a keep-out scan that stops credentials, personal paths and private terms from being published.
- Set up the repository: a uv workspace with the generic core (`pydantic-ai-factory`) and the software domain package (`pydantic-ai-factory-software`), formatting, linting, strict typing, tests, an import-rule check and CI on Python 3.11 to 3.14.
