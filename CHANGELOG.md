# Changelog

Every change a user can see is listed here, newest first.

## Unreleased

- Ask for prompt caching in the software factory's `designer` and in every Elephant Goldfish goldfish, with `model_settings={"cache": True}`. In the first real runs neither was cached, and the designer resends its whole conversation every review round. The Getting started designer and the evaluation set's designers ask for it too. The Getting started reviewer now uses `Coder(sub_agents=False)`: in a real run it handed the whole review to a sub-agent, which read the project again and doubled the review's cost.

- Add an evaluation set for the Design station, built on `pydantic-evals`: `python -m evals.design --offline` runs four to-do list missions through a one-station factory twice, with a designer that has `ElephantGoldfish` and the same agent without it, and scores both with plain code (`CoversTheMission`, `EnoughCriteria`, `CriteriaTiedToTheMission`, `SettlesTheUnsaid`, `attempts`, `rounds`, `open_findings`). Each case has hidden checks, questions its mission leaves open that a good design must settle, such as what a blank task does; `SettlesTheUnsaid` is the share a design answers. `--model NAME --out results.json` runs it against a real model. CI runs it offline. Add the Measuring a methodology and Roadmap pages, and an acceptance test for each row of the roadmap's "Today" table.

- Add the `factory` command, installed with `pydantic-ai-factory-software`. `factory run "MISSION"` (or `--brief FILE`) runs the software factory, prints the design in full, says how it was reviewed and asks you to approve it, ask for changes or reject it; an approved design is written to `designs/<title>.md`. An agent's question is asked in the terminal too. `--offline` uses a scripted model, so no key is needed. `--no-input` saves a waiting run instead of asking; answer it later with `factory resume <run id>` and `--approve`, `--changes NOTE`, `--reject NOTE` or `--answer TEXT`; a waiting run prints the command that answers it, with `--answer` when an agent asked a question and `--approve` otherwise. `factory show <run id>` prints a run, and the design it waits on. Exit codes: 0 passed, 1 ended without passing, 2 the command was wrong, 3 waiting. Add the Getting started page, a `live` pytest marker for tests that call a real model, skipped unless selected with `-m live`, and the to-do list brief in `examples/todo-list/brief.md`.

- Add the software factory, in `pydantic-ai-factory-software`. `SoftwareFactory(model, rounds=2, repairs=2, goldfish=DESIGN_GOLDFISH, review_model=None, accept=None)` is a `Factory` named `"software"`, with one station today, `design`. A string mission becomes a `Mission`. The `designer` agent drafts a `Design` (`title`, `goal`, `behaviour`, `acceptance_criteria`, `exclusions`, `open_questions`) under `ElephantGoldfish`, reviewed by the three `DESIGN_GOLDFISH` (`comprehension`, `critique`, `readiness`) against `DESIGN_STANDARDS`. A design that still has open questions fails the gate `no_open_questions` and is sent back up to `repairs` times, then a person decides; a design that passes waits for a person to approve it. `render_markdown(design)` turns a design into Markdown, numbering acceptance criteria AC1, AC2 and so on and dropping any label such as "AC1:" that the designer wrote itself. The designer is told not to repeat a finding it contested or escalated as an open question, so that finding does not fail `no_open_questions` and cost a second attempt. The package has an `anthropic` extra. Add the Software Factory pages: the overview, Design, and Build, Quality and Release (coming soon).
- Change the Elephant Goldfish and Methodologies samples to use `DESIGN_GOLDFISH`.

- Add tracing. Every call to `Factory.run` or `Factory.resume` is an OpenTelemetry span under the `pydantic_ai_factory` tracer, with a span inside it for each station attempt, each `ctx.run_agent` call, each gate evaluation and each answer a person gave. Pydantic AI's own spans, and the goldfish reviewing a draft, nest inside their station. Spans carry digests, never content, and never a person's note or reply. Nothing is traced until the application installs a tracer provider. `opentelemetry-api` is now a direct dependency.

- Add Elephant Goldfish, Google's method for design-driven development, in `pydantic_ai_factory.methodologies`. `ElephantGoldfish(goldfish=..., rounds=2, model=None, max_questions=3)` is one methodology: each draft the author finishes is read by fresh goldfish agents, stage by stage (`comprehension`, `critique`, `readiness`), and their findings go back to the author with `ModelRetry` until a round has no `Blocker` or `Major` or the rounds run out. The author can `contest` or `escalate` a finding; those, and findings still open at the limit, make the station wait for a person. A goldfish that fails means the station did not run. Each round is a `GoldfishReport`, judged by the gate `clean_final_round`. It includes `AskPerson`, so the author may ask up to `max_questions` scoping questions; a question asked mid-review keeps the round count and the findings already answered. The goldfish count in the author's usage and stop at its usage limits. Define reviewers with `Goldfish(name, stage, job, standard=None)` and `Standard(name, text)`.

- Add methodologies. `Methodology` subclasses Pydantic AI's `AbstractCapability` and adds `name`, `version`, the `evidence` types it records with `self.record(ctx, payload)`, and `judge`, its gate. Attach it to an agent with `capabilities=[...]`. In a station, `ctx.run_agent` stores the evidence, joins the methodology's gate to the station's into one combined gate, stamps its name and version on the records, and adds its `output_retries` to the agent's output retry budget. A replayed agent call gives back its evidence. `Station.methodologies` and `Factory.methodologies()` list them before a run, and the factory digest covers them.
- Remove the `methodologies=` argument of `Factory.run`, `Factory.run_sync` and `Station.run`, and the `Run.methodologies` field. Methodologies live only on agents.

- Add missions and signals. `Mission(objective, success_criteria=..., constraints=...)` is what a factory commits to; when the first station takes a `Mission` or a `str`, `Factory.run` turns a plain string into one, and a station that takes a `str`, such as `station(agent)`, is given `mission.as_prompt()`. The run keeps the mission as an artifact, named by `run.mission_ref`, and every artifact it makes carries the mission's id. `Signal(payload, source=None)` is work that arrives on its own; the payload's type is its kind. `Factory(..., accept=...)` and `factory.intake` (or `intake_sync`) store each signal and return a `Mission` that records them, or `Declined(reason)`. When a run of a mission made by intake ends, the factory stores an `Outcome` signal and names it in `run.outcome_signal`.
- Remove the `mission_id=` argument of `Factory.run` and `run_sync`. A run's mission comes from its input.

- Add approvals. `@station(approval=True)` and `station(agent, approval=True)` make a run wait for a person once every gate has passed. A waiting run has `run.waiting`, of kind `"approval"`, `"escalation"` or `"tool-calls"`. Answer with `run.approve`, `run.request_changes` or `run.reject`, each bound to the exact output, or, for tool calls, with Pydantic AI's `DeferredToolResults`, and carry on with `Factory.resume` or `resume_sync`. `run.approvals` records every decision.
- Add escalation: the `escalate` verdict, `raise Escalate(reason, output=...)` in a station, and `Rework(..., on_limit="escalate")`. Approving an escalation accepts the work and records that a person overrode it.
- Add tool-call waits. An agent run through `ctx.run_agent` that ends with deferred tool calls makes the run wait; on resume the station runs again, replaying the agent calls that finished. Add the `AskPerson` capability, an `ask_person` tool capped by `max_questions`. An agent with output validators keeps its own output type; to let it wait, declare `DeferredToolRequests` in it.
- Add the `RunStore` protocol. `MemoryStore` and `LocalStore` keep runs as well as artifacts, with `get_run`, `get_run_sync` and a compare-and-swap `put_run`; an answer is saved before the work it starts, so a second answer to the same run raises `RunConflict` and runs nothing. The factory saves the run after every step; `on_step` is for watching. `get_sync` reads an artifact from code that is not async. The stores move to `pydantic_ai_factory.stores`, with `encode_run` and `decode_run`.
- Remove the `needs_approval` verdict; use `approval=True` or `escalate`. Remove the Artifacts page; artifacts and runs are on the Stores page.

- Add agents in stations. `ctx.run_agent(agent, prompt)` runs a Pydantic AI agent, stores its `Conversation` keyed by the agent's name, and carries it on at a later attempt, sending the gate's reasons instead of the prompt. `@station` finds the agents its function refers to; `agents=` names them instead. `station(agent)` turns one agent into a station. `Factory.agents()` lists every agent before a run. `Factory.run_sync` and `Station.run_sync` run from code that is not async.
- Change stations and artifacts to take any type Pydantic can serialise, such as `str` or `list[str]`, not only models.
- Change `Rework` to take station objects: `Rework(design, limit=2)` and `Rework(build, to=design)`.
- Change the `Run` record: `output` is now the final payload, and the refs are `input_ref` and `output_ref`. `StationResult` has `input_ref`, `output_ref` and `conversations`.
- Change `StationContext` to `run_agent`, `record`, `deps`, `attempt`, `feedback` and `run_id`. `feedback` is a `Feedback` record of the reasons work came back.
- Remove the Concepts page. Each concept has its own page.

- Add factories: `Factory`, `Rework`, `Factory.run` and the `Run` record. A factory is a named, ordered list of stations; there is no separate line. Failed work can be sent back a bounded number of times with the gate's reasons; a station that did not run is never retried. A badly formed factory is refused with every finding at once. `on_step` saves progress after every attempt.
- Add gates: the `@gate` decorator, `passed`, `failed` and `needs_approval` verdicts, required evidence, `Gate.evaluate` and `GateDecision` records. A gate that cannot be evaluated is reported as such, never as a pass or a fail.
- Add stations: the `@station` decorator, `StationContext`, `Station.run` and `StationResult`, which keeps "ran" apart from "passed" and carries the traceback of a station that raised. Every definition error is a `DefinitionError` whose `findings` list each problem.
- Add artifacts: `Artifact`, `ArtifactRef` and `Producer`, with SHA-256 content digests, lineage and superseding. Add the `ArtifactStore` protocol with `MemoryStore` and `LocalStore`, which check every artifact against its digest. `Untyped` reads an artifact without its payload class, and `encode_artifact` and `decode_artifact`, in `pydantic_ai_factory.artifacts`, let you write your own store.
- Add the documentation site, with Overview, Concepts and Decisions pages, diagrams, a check that every diagram parses, and a test that runs every Python sample in the docs.
- Add a keep-out scan that stops credentials, personal paths and private terms from being published.
- Set up the repository: a uv workspace with the generic core (`pydantic-ai-factory`) and the software domain package (`pydantic-ai-factory-software`), formatting, linting, strict typing, tests, an import-rule check and CI on Python 3.11 to 3.14.
